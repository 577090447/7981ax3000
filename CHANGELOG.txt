[修复内容]

1. Rust 编译失败 (package/feeds/packages/rust [host] failed)
   - 原因: Rust 默认 download-ci-llvm=true，官方已清理旧版 LLVM 构建产物
   - 修复: r30b1.yml 中新增 "Patch rust to avoid LLVM 404" 步骤
   - 修复: diy-part2.sh 中物理级禁用 CONFIG_PACKAGE_rust
   - 修复: OpenClash 强制使用 binary core (CONFIG_OPENCLASH_CORE_TYPE="binary")

2. OOM 内存不足
   - 原因: Rust + ZSTD_O3 + YJIT 在 GitHub Actions 7GB 环境易爆
   - 修复: r30b1.yml 初始化环境新增 4GB Swap
   - 修复: diy-part2.sh 关闭 CONFIG_RUBY_ENABLE_YJIT

3. iStore 集成方式错误
   - 原因: 原 diy-part1.sh 直接 git clone 到 package，不走 feeds
   - 修复: 改为官方标准方式 (src-git istore + feeds update + feeds install)

4. Argon 主题不生效
   - 原因: 原 sed 修改 Makefile 路径在 25.12 已失效
   - 修复: 改为 uci-defaults 脚本，首次启动自动设置 Argon 为默认主题

5. diy-part1.sh 提前执行 feeds update/install
   - 原因: part1 定位是 Before Update feeds，不应执行 feeds 命令
   - 修复: 移除 part1 中的 feeds 命令，交给 workflow 标准步骤

[r30b1.config 改动]
- 关闭 CONFIG_RUBY_ENABLE_YJIT (防 OOM)
- 新增 CONFIG_OPENCLASH_CORE_TYPE="binary"
- 新增 # CONFIG_PACKAGE_rust is not set
- 新增 # CONFIG_PACKAGE_librust is not set
- 统一所有 =n 写法为标准 # CONFIG_... is not set

[使用方法]
1. 将 r30b1.yml 覆盖到 .github/workflows/r30b1.yml
2. 将 diy-part1.sh 覆盖到仓库根目录
3. 将 diy-part2.sh 覆盖到仓库根目录
4. 将 r30b1.config 覆盖到仓库根目录
5. chmod +x diy-part1.sh diy-part2.sh
6. git add . && git commit -m "fix: 25.12 全量修复 Rust/OOM/iStore/Argon"
7. git push → GitHub Actions → Run workflow
